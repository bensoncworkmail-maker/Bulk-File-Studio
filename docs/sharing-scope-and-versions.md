# 共享範圍與版本

## v1.69.0 共享差異合併

發布時在共享資料夾寫入有版本的快照。接收時選「共享差異合併」，使用上次確認的來源版本、本機版本及新發布版本逐欄比較。不同欄位可合併；同一欄位兩邊改成不同內容會停止該次寫入。表格與群組結構按各自項目比較。

首次接收可加入新資料、確認相同內容並建立基準。若本機已有不同內容，先核對雙方版本，可選其他既有模式明確建立基準。合併保存本機獨立資料、回收狀態與來源包未包含的紀錄。成功後會記錄基準，重試相同版本不會重複改寫紀錄。已啟用自動接收的來源有可用基準時，本機曾編輯仍可接收不衝突的來源更新。

這個功能改變的是接收與套用方式。傳輸沿用完整版本快照，沒有刪除同步或跨來源的 Git 提交圖。

## 舊版範圍與快照規則

## 一開始的預設

v1.45.0 以前共享發佈為全部有效主表與明細。v1.46.0 預設仍相容，但可在「共享更新 → 共享設定與來源資訊」指定發佈與接收範圍；兩個選項互相獨立。選好主表後按「套用範圍」。這些設定保存於 workspace-share.json，不隨一般介面偏好還原或匯出到另一台電腦。

| 發布範圍 | 接收範圍 | 實際影響 |
| --- | --- | --- |
| 全部 | 全部 | 資料包全部內容；來源複製為完整取代 |
| 指定 A | 全部 | 只套用 A 與其明細；其他主表保留 |
| 全部 | 指定 A | 只套用 A 與其明細；其他主表保留 |
| 指定 A、B | 指定 B、C | 交集 B 及明細；沒有交集則停止 |

指定主表使用相同 ID，標題相同並不代表同一張表。陌生來源尚未匯入時，本機不會先知道其表格 ID；先依來源包範圍預覽、匯入後再設定接收主表。另存副本會產生新 ID，不能拿副本 ID 持續追蹤原來源。

## 明細、外部關聯與回收筒

指定主表連同其全部明細，包含來源後來新增的明細；接收不會把其他主表的紀錄帶入。若有跨主表關聯，資料包保留驗證所需的參照表格結構，不包含該外部主表的紀錄；不在範圍內的關聯紀錄值會省略。這些來源參照結構不會覆蓋本機已存在的外部表格。

更新模式合併相同 ID，保留本機獨有資料。指定範圍的來源複製則完整替換該主表家族，包含其中的回收筒資料；其他主表及其回收筒保持原樣。若其他表格仍引用某筆將移除的紀錄，或本機結構不相容，預覽會停止，不會為了完成匯入而清掉範圍外的關聯。請先整理關聯或改用更新模式。

舊版資料包未標示範圍時視為全部；不要直接把舊的局部匯出包當作安全的指定來源複製。先核對預覽的移除項目，必要時使用更新模式。備份仍保留本機工作區 ID，可從「還原備份」恢復。

## 三種版本

| 顯示 | 意義 |
| --- | --- |
| 發布 #N | 同一發布來源成功發佈的序號；同一資料修訂可以發佈多次 |
| 資料修訂 rN | 發布端整個工作區的修訂，用來偵測來源前進／倒退 |
| 本機紀錄 vN | 此電腦單筆紀錄的版本；與其他電腦的 vN 不必相等 |

舊快照保留原檔名，不覆寫。清單按「版本資訊」才讀取該包，避免每次掃描大量 JSON；資料夾檢查仍最多列出 50 份，請自行保留需要的版本。來源 ID 和發布編號不是數位簽章，不代表操作者身分。發布序號保存於共享設定檔；不要跨電腦複製此檔或共用來源 ID。

回到舊版：版本資訊 → 比較此版本 → 選來源複製 → 核對新增／更新／移除 → 取代與二次確認。更新模式只合併，不會移除較新版新增的本機獨有紀錄。操作前自動備份；如果手動接受較舊來源修訂或發布號，程式改為提醒模式，讓新版仍可提示而不自動覆蓋你的回復。

改接收範圍或跟隨來源後，舊自動接收基準失效，需重新手動預覽及確認。v1.47.0 的自動接收採固定更新模式，要求本機未修改且無表單或預覽。v1.69.0 的差異合併行為見上節。


## v1.47.0 相容性保護

新指定主表共享包採封裝 4；不識別範圍的舊接收端會拒絕讀取，需先升級。一般完整工作區仍匯出封裝 3，新版繼續讀取舊封裝 1／2／3。從本機匯入封裝 4 也會採用其範圍，不會因手動選檔而變成全工作區複製。
